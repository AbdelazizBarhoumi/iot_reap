# Fix: Google OAuth Users - Delete Account & Password Change

## Problem
Google OAuth-registered users cannot:
1. **Delete their account** — `ProfileDeleteRequest` requires `current_password` validation, but these users never set a password (a random bcrypt hash is generated during signup at `GoogleOAuthService.php:176`)
2. **Change their password** — `PasswordUpdateRequest` requires `current_password` validation, same issue

## Approach
Detect Google OAuth users (those with `google_id` set) and skip the `current_password` requirement for both flows.

---

## Changes

### 1. Add helper method to User model
**File:** `app/Models/User.php`
- Add `isGoogleUser(): bool` method that returns `true` when `google_id` is not null
- This provides a clean, reusable check across the codebase

### 2. Fix delete account validation
**File:** `app/Http/Requests/Settings/ProfileDeleteRequest.php`
- Modify `rules()`: if the authenticated user `isGoogleUser()`, skip the `current_password` rule
- Google OAuth users can delete without password; email/password users still must confirm

### 3. Fix password change validation
**File:** `app/Http/Requests/Settings/PasswordUpdateRequest.php`
- Modify `rules()`: if the authenticated user `isGoogleUser()`, skip the `current_password` rule
- This lets Google OAuth users set a password for the first time without knowing the random one

### 4. Update delete account UI for Google OAuth users
**File:** `resources/js/components/delete-user.tsx`
- Pass `user` from page props (already available via `usePage().props.auth.user`)
- Conditionally hide the password input field when `user.google_id` is set
- Adjust the dialog description text for Google OAuth users (no password prompt needed)

### 5. Update password settings UI for Google OAuth users
**File:** `resources/js/pages/settings/password.tsx`
- Pass `user` from page props
- Conditionally hide the "Current password" field when `user.google_id` is set
- Update the description text accordingly (e.g., "Set your password" vs "Update password")
